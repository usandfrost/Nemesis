# Presets and wavetables

What is in the firmware, how it got there, and what is left for the board. (Listening-page ratings: `content/data/ratings.json`; the fit analysis: `content/out/fit_report.md`.)

## The preset list
- 200 presets in one numbered list (`app/Params.h`: `presetName/Cat/Voices/Banks`, `presetLoad`, `applyPresetIndex`): the factory's first three (numbers 0-2, built into the firmware; 3-9 are not used: seven of the original ten were taken out on 2026-10-28), then 197 **files on the card** (next section): 59 converted from the original CATHODE presets (the first round: 131 rated **3 or more** on the listening page, filed under the category the user wrote in the export's `note`; 15 of them were later voted out as too similar and 57 more skipped on the golden page, see below; now BASS 16, POLY 9, PAD 7, KEYS 6, STAB 4, BELL 4, FX 3, LEAD 3, PLUCK 3, SEQ 2, TEXTURE 2), the second round (37), and the genre sets (101).
- Data: `content/presets/*.PRS`, generated by `tools/gen_presets.py` from `content/data/cut.json` (`content/tools/cut_presets.py` makes the cut). 12 categories in BROWSE: ALL BASS LEAD PAD PLUCK STAB POLY KEYS FX SEQ TEXTURE BELL.
- Loading a preset (OK in BROWSE) sets the nine pages, the part's voice count to what the preset was made for (the factory's three leave it), and, undone by SHIFT + ○, restores all three. A project stores the number (`Part::preset` is 16 bits from project version 5; older files are converted on load).
- Effects: each library preset also carries its original upstream effects chain, mapped to the Drumboy's FX section (`content/data/fxmap.json`, rules and calibration in `content/out/FX_MAPPING.md`; `tools/gen_presets.py` writes it into each file). Loading a preset sets its part's DELAY / REVERB / CHORUS sends and its amp completely (a preset without effects leaves the part dry); the shared effects (delay time, reverb decay, chorus rate...) take the preset's settings only if no OTHER part sends to them, so another part's reverb is not changed under it. The part's voices are trimmed if the preset plus its amp and shared effects would not fit the 5-voice budget (a toast says so). Undo restores the effects exactly. The BROWSE preview plays through the preset's effects. Of the first round's 131: 65 send to the delay, 47 to the reverb, 39 to the chorus, 15 get an amp; 21 had no effects. Not mapped: compressor, EQ, phaser, schain, vintage, and a delay feeding a reverb in series (parallel sends cannot do that).
- Not converted (the panel has no place for them): per-oscillator envelopes, PD types other than Saw, ALGO and Bitmask oscillators, velocity to cutoff (folded into the base cutoff), further LFO routes, glide, the punch transient. See `content/out/fit_report.md`.

## The preset library on the card (add presets without building the firmware)
- **Where:** `/CATHODE/PRESETS/` on the card: one `.PRS` file per preset (148 bytes) and an `INDEX.PIX` the firmware keeps. `tools/make_sd_content.py <dir>` lays the 197 files out with the wavetable banks and the firmware image. The format is `firmware/src/app/PresetFile.h` (and `tools/prs.py`): magic `DBPR`, id, category, voices, the two banks, name (1-20 printable characters), the 72 knob values, the sends, the amp and the shared effects' settings, CRC-32.
- **Numbers:** a preset's number is its **id**: the factory's are 0-2, the library's 10-140 (the numbers they had when they were compiled in, so saved projects still show the right name), and your own start at 1000. A number does not change meaning (unless you delete the top preset's file: the next save takes the next id above the highest one left, so that id can be handed out again); two files with one id: the file with the smaller name wins and the other is counted as ignored. The BROWSE list is in id order, so new presets come last in their category.
- **Memory:** the firmware keeps only the index in memory (SDRAM): 64 bytes a preset, up to 1024 presets (64 KB). A preset's file is read when it is **previewed or loaded** (a few ms), into a cache of the 16 last used (2.4 KB). At boot, with an up-to-date index, the firmware lists the folder (no file opened) and reads `INDEX.PIX` in pieces of 8 entries (about 25 reads for 197 presets); no preset file is opened.
- **The index is a cache of the folder.** It stores a fingerprint of the folder's listing (each `.PRS` file's name, size and date). At boot the firmware lists the folder (no file is opened), and if the fingerprint matches it reads the index; if it does not (a file added, replaced, renamed or removed, or no index yet) it reads every file once, rebuilds the list and writes a new `INDEX.PIX` (a card that cannot be written is read in full at each start instead). So **to add a preset: copy its `.PRS` into `/CATHODE/PRESETS` and restart.** The first start after a change reads all the files (about 200 files; not measured on the board). Delete `INDEX.PIX` to force it.
- **A card that fails while the files are read** (a bus error on some of them) does not leave a hole: no index is written, so the next start reads everything again. Hidden files and dot-files (macOS's `._name.PRS`) are not looked at. With more files than the list holds, the smallest ids are kept, whatever order the folder lists them in. The list's size is part of the index's fingerprint, so an index made for a smaller list is not used for a bigger one.
- **Bad files are skipped, not trusted:** wrong size, magic, version or checksum, an id below 10 or above 32000, a category outside BASS..BELL, voices outside 1-5, a bank above 199, a name that is empty, over 20 characters or not printable ASCII, a file name with anything but letters, digits, space, `_ - . ( )`, a duplicate id, or more files than the list holds. A toast at boot says how many were left out. Knob values outside their range are brought into it. An index that fails its checks is built again. If a file cannot be read when the preset is chosen, BROWSE says PRESET FILE CANNOT BE READ and nothing changes.
- **Saving from the panel:** on the sound pages or in BROWSE, **SHIFT + OK** opens SAVE PRESET for the part you are on (a synth part). Knob 1 moves the cursor in the 20-character name and knob 2 changes the character (the arrows do the same: left/right move, up/down change; SHIFT turns it faster), knob 3 is the category, knob 4 is NEW or REPLACE. The name starts as the loaded preset's ("Acid Roll" becomes "Acid Roll 2" for a new one). **OK** saves and returns; L cancels. NEW gives the next id from 1000 (`PRESET ID` shows it). REPLACE is offered when the part's sound was loaded from a preset on the card (id 10 or more; the factory presets can only be saved as new): it asks for OK a second time within four seconds, then rewrites that preset's file (under the same file name; the name inside changes) and keeps its id. What is saved: the nine pages' 72 values (a wavetable by its bank), the voices, the part's sends and amp, and the delay/reverb/chorus settings it sends to. The preset is on the BROWSE list at once and the part shows it as loaded. A new preset is a new file and a replace writes over the file in place (148 bytes, one sector; a torn file would fail its checksum and be left out); the index is updated, so the next start needs no rebuild. The screen says SAVING PRESET while the card works. The editor ignores an OK within 0.4 s of opening it (a bounce of the SHIFT + OK that opened it) until a knob or arrow is touched, and it will not open while a step lock is open on the sound page. There is no undo; a replaced library preset can be rebuilt from `content/presets`. Not saved: p-locks, arp/chord settings, the part's level and priority, the compressor.
- **Making presets on a computer:** `tools/prs.py export "content/presets/0010 Acid Roll.PRS" > mine.json`, edit the JSON (name, category, voices, banks, the nine pages' eight values, the effects), then `tools/prs.py new mine.json -d <folder>` writes `<id> <name>.PRS` with the next free id from 1000 (the "id" in an export is only information; `--id N` picks one). `prs.py check <folder>` validates a folder, `prs.py show` lists files. The page values are the knob numbers the panel shows (WAVE 0-3 in the pages when the oscillator is not on a bank; a bank is the `banks` entry, and its position is POSITION in the OSC page's second knob). 
- **Also:** a project that uses a preset the card does not have shows no preset name for that part (the sound itself is saved in the project). Changing the card's files needs a restart: they are read at boot only. The flash this freed is about 10 KB (the data was about 20 KB; the loader and checks take the rest).

## The preset editor on the website

`web/www/librarian.html` has an editor: a preset from the device, from a file or a new one, every value on a slider or a list, saved as a `.PRS` or sent through the librarian's protocol (`docs/PRESET_SYSEX.md`). Today it reaches the simulated device only, like the rest of the librarian.

- **The data is the firmware's.** `tools/gen_preset_schema.cpp` (built with the host tests as `preset_schema`) writes `web/www/preset-schema.js` from `app/Params.cpp`, `app/FxParams.cpp`, `app/WaveLib.cpp` and `app/PresetFile.h`: page and knob names, ranges, defaults, list choices, what the panel writes for every value, the banks in `content/data/wavetables`, and where each field sits in the file (found by encoding test records). After a change to those tables: `tests/build/preset_schema content/data/wavetables > web/www/preset-schema.js`. `tools/check_all.sh` fails if the committed file differs.
- **What is not generated:** the lines of help, the rules that dim a knob (`state()` in `web/www/preset-editor.js`: the panel's in `Ui.cpp`, and a few from what `LeanPart.cpp` does) and the list of knobs the firmware ignores (`NOT_USED`). `web/test/preset-edit.mjs` checks the help against the knobs, and that the firmware still has those rules and still ignores those knobs.
- **One value, one byte.** `web/www/preset-model.js` holds the file's 148 bytes and writes only the bytes of the value that changed and the CRC. A retired knob's slot, a value outside its range and the settings of an effect the preset does not carry stay as they are. Ticking an effect a file never held (all zeros) puts the panel's defaults in those eight bytes, and unticking it again puts back what the file had. An older file's detune in the retired OSC 1 slot still counts, because the firmware plays the larger of it and UNI DET: the knob's line says so.
- **Numbers.** A new preset gets the number the firmware's `presetNextId` would give, past the highest in use from 1000 up. The page reads the list again before every send, so the question names what is on the device at that moment.
- **Checked by:** `web/test/preset-edit.mjs` (every value of every knob, each bank, category, voice count, name character and effect combination, on a new preset and on real ones: 45,132 records, through `parsePreset`, `tests/app/preset_accept.cpp` on `PresetFile.h`, and `tools/prs.py`), and `web/test/site.mjs` (the page, with real pointer events). None of it has run against a real Drumboy Pro.
- **Hearing it:** Hear it writes the edited bytes into the engine worker's in-memory library as one more file (`audition` in `web/www/engine-worker.js`) and loads it as the panel would, on the lean voice. It needs the same two headers as Online Nemesis.

## Wavetables
- 200 factory banks of the original CATHODE, all generated by code there. The OSC pages' WAVE knob: 0-3 = SIN TRI SAW SQR (as before), 4 + n = bank n of the catalogue (`app/WaveLib.*`, `WaveNames.inc`: names by `tools/gen_wave_names.py`). On a bank PD SHAPE becomes POSITION (0-127 across its 32 frames), PD AMT does nothing, and the LFO and ENV routes that moved PD AMT move the position. A bank whose file is not on the card shows its name in red with a "?" and plays the basic wave it is nearest to. WAVE is not p-lockable; POSITION is.
- Files: `/CATHODE/WT/wtNNN.wtp` on the card, made by `tools/wt_pyramid` (builds with the tests: `tests/build/wt_pyramid content/data/wavetables content/data/wtp`). A `.wtp` is the finished band-limited pyramid as 16-bit samples (about 0.55 MB): the board reads it and runs no FFT. `tools/make_sd_content.py <dir>` lays out the firmware image and the 52 banks the presets use (27 MB; 55 banks have 32 frames, bank 166 has 16).
- Memory: a bank is 32 frames x 8,576 samples = 1.10 MB in memory (float; a few banks have 16 frames and take half). A fixed arena of up to three banks is allocated at boot (fewer if SDRAM is short; at least 4.5 MB of SDRAM stay free for the audition buffers, the reserve and the sample cache, so with three banks the cache can be about 1 MB: many card samples next to three banks may give SAMPLE MEMORY FULL). A bank nobody asks for is let go, and its slot re-used 25 ms later. A fourth bank at once shows WAVETABLE MEMORY FULL and that part plays the basic wave.
- The oscillator reads each band-limited level at its own length (`tools/fork_patches.py` W1: 4x its Nyquist length, never under 128 samples). Compared with the full-length pyramid over the 56 banks the output differs by a median 0.8% (-42 dB), worst 3.8% (5 banks over 3%); the spurious tones from the interpolation stay below about -55 dB. Without `decimate` the code path is the original, bit for bit. (64 samples as the floor and 4x gave worst 5.6% and -47 dB spurs; 8x with a 128 floor would give worst 1.4% for 1.34 MB per bank.)
- Not yet checked on the board: how long a bank takes to load from the card (a 0.53 MB read plus conversion into SDRAM, estimated tens of ms), and what the uncached SDRAM does to the oscillator's reads (the D-cache is off; docs/OPTIMIZATION_PLAN.md).

## Similarity vote (2026-10-27)

`content/tools/similarity.py` compared every preset with the others of its category (the sound from the dry render: spectrum, loudness shape, brightness, noisiness; and the settings: oscillators, filter, envelopes, LFO, sends) and `content/tools/build_similarity_page.py` made the voting page: 56 groups holding 150 presets; the other 242 had no close neighbour. The user voted on all 150: 77 kept, 73 cut. The 73 are listed in `content/data/similarity_cuts.json`; `gen_presets.py`, `cut_more.py` and `genre_presets.py` leave them out (their ids stay unused, the ratings files are untouched). To bring one back, delete its entry and rebuild. Library after the vote: 10 factory + 385 files = 395 presets (first round 116, second round 75, synthwave 26, techno 29, synth pop 27, trance 19, EBM 27, Röyksopp 32, Delerium 30, voice pads 4).


## Golden vote (2026-10-28)

The Golden Presets page (`content/tools/build_golden_page.py`; the whole library, the factory ten included, played with its effects) asked for Keep or Skip on every preset: 200 kept, 195 skipped, none left unheard. The choices are in `content/data/golden_votes.json` (the 188 skipped library presets; the factory ones are listed apart). `gen_presets.py`, `cut_more.py` and `genre_presets.py` leave the skipped ones out through `prs.library_cuts()` (together with the similarity cuts); their ids stay unused, the batch files and ratings files are untouched. To bring one back, delete its entry from `golden_votes.json` and rebuild. The 7 factory presets that were skipped (Algo Knock, Glass Wide, Saw Stack, Pluck Fifth, Tape Warble, Soft Sheen, Bare Slab) were then taken out of the firmware (`kPresets` is three long; the three kept are now ids 0-2 and ids 3-9 are reserved, the library's ids start at 10 as before). A new project's parts A, B and C start with the sounds of `kBootSounds` (the same pages as before for Algo Knock, Glass Wide and Soft Sheen) and show no preset name. A saved project that stored a removed factory number shows no name for it.

Library after the vote: 3 factory + 197 files = 200 presets (first round 59, second round 37, synthwave 19, techno 16, synth pop 12, trance 11, EBM 10, Röyksopp 19, Delerium 12, voice pads 2).

**Delay levels (2026-10-28).** Seven SEQ presets had too much delay (their delay send was 50-111 of 127 against 22-29 for Detroit Seq and Triplet Arp): Sunset Arp, Neon Cascade, Laser Rain, Hypno Pulse Seq, Octave Saw Arp (batch files), Turbo Steps (triplet like Triplet Arp) and Dotted Chords (a converted preset: `content/data/fx_fixes.json`, applied by `cut_more.py`). The added effect level in the render (the difference between the WITH FX and DRY renders) went from -0.0..-5 dB to -6..-12 dB, Detroit Seq's is -6.6 and Triplet Arp's -7.2.

## Names (renames, 2026-10-27)

A preset's name should not promise an instrument or a voice the sound does not resemble. 83 library presets (and the factory "Saw Choir", now "Saw Stack") were renamed for that reason; the old-to-new map is `content/data/renames.json`. The builders (`gen_presets.py`, `cut_more.py`, `genre_presets.py`) write the new name; ids, batch files and the ratings, which are keyed by the old name, are untouched. `tools/prs.py check DIR --renamed` (used by `check_all.sh`) fails if a file still carries an old name or two presets share a name. Sound-type words (bell, chime, pluck, stab, pad, bass, lead, keys) and the percussion lane names (hat, snare, rim shot) stay. To rename another preset, add it to the map and rebuild.

The choir/voice wavetable banks (31 FORMANT, 32 CHOIR, 37 NASAL, 43 THROAT, 44 BREATH, 45 WHISPER, 48 CHOIR WIDE, 49 CHOIR MEN, 50 CHOIR HIGH) are present and play, but each frame is one 2048-sample cycle with its vowel-like peaks at fixed harmonic NUMBERS (for example NASAL has its peaks around harmonics 11-22), so the "vowel" moves with the note instead of staying at fixed frequencies as a voice does, and there is no breath, consonant or ensemble movement. They give vowel-coloured organ-like tones, not voices.
